# TASKS --- план разработки

Выполняйте задачи по порядку. Не отмечайте задачу готовой, пока
результат не проверен. Подробные инструкции --- в `TASKS_GUIDE.md`.

Последовательность разработки:
1. **Сайт (Frontend & UI/UX)** — интерфейс, дизайн-система, каталог, корзина, оформление, личный кабинет, админка и адаптивность (на локальных/моковых данных).
2. **База данных (Neon PostgreSQL)** — подключение Neon, Prisma/схема БД, миграции, перевод API, аутентификации, заказов и админ-панели на реальную БД Neon.
3. **Telegram Mini App** — адаптация под Telegram WebApp SDK, авторизация через Telegram initData, корзина и оформление внутри Telegram.
4. **Мобильное приложение** — мобильный клиент, API-аутентификация (JWT/Bearer), каталог, корзина, push-уведомления и оформление.

## Часть 2. База данных (Neon PostgreSQL) и Backend

### Этап 7 --- подключение Neon и моделирование схемы

- [ ] **T071.** Настроить Prisma (или Drizzle) в проекте, связать с `DATABASE_URL` от Neon.
- [ ] **T072.** Описать схему БД: `User`, `Category`, `Product`, `Order`, `OrderItem`, `Payment`.
- [ ] **T073.** Выполнить первую миграцию в Neon и настроить сид-скрипт (seed) для наполнения реальными категориями и товарами.

### Этап 8 --- интеграция бэкенда, аутентификация и API
- [ ] **T080.** Настроить NextAuth / Auth.js с адаптером базы данных Neon (Email/Password с хешированием bcrypt/argon2 и Google OAuth).
- [ ] **T081.** Реализовать серверные API маршруты для каталога, категорий и товаров с выборкой из Neon.
- [ ] **T082.** Реализовать серверный API заказов (`POST /api/orders`) с серверной перепроверкой цен, остатков и транзакционным сохранением в Neon.
- [ ] **T083.** Подключить API личного кабинета: сохранение профиля, истории заказов пользователя из базы Neon.
- [ ] **T084.** Подключить админ-панель к реальным CRUD-эндпоинтам с серверной проверкой роли `ADMIN`.

**Готово по БД:** Сайт полностью подключен к облачной БД Neon, данные персистентны, заказы и пользователи сохраняются надёжно.
